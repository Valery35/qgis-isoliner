# Инструменты вычитки текстов

Набор сложился при сплошной вычитке контекстной справки в 5.13.16. Все
скрипты запускаются из корня рабочей копии, без аргументов или с одним
файлом пачки.

## Зачем отдельные инструменты

Справка инструмента это склейка десятка строковых литералов, разорванная
переносами в произвольных местах. Каждая русская строка живёт в двух
местах сразу, литералом в коде и ключом словаря в `i18n.py`. Замена фразы
по тексту файла находит её не всегда, а найдя в одном месте и не найдя в
другом, разводит литерал и ключ. Правка идёт по значению узла
`ast.Constant`, у неявной склейки узел один.

## Поиск

| Скрипт | Что делает |
|---|---|
| `ui_strings.py` | собирает все строки, видимые пользователю, в `/tmp/claude-0/ui_keys.json`. Запускать первым и после каждой пачки |
| `ck.py` | ищет по собранным строкам список шаблонов, печатает контекст. `python3 manual/tools/ck.py 'наивн\w*' 'важнее'` |
| `colons.py` | вытаскивает предложения с двоеточием внутри. `python3 manual/tools/colons.py 0 85` печатает окно списка |
| `len.py` | средняя длина предложения, количество длиннее 28 и 34 слов, сами длинные |
| `manscan.py` | тот же скан по руководствам, README и CHANGELOG |
| `helpscan.py` | все 74 справки инструментов разом: длина, ритм, стоп-слова, пунктуация. Таблица сортирована по номеру, править сверху вниз |
| `manlabels.py` | подписи параметров в таблицах глав `manual.md` против подписей в окне. «(доп.)» руководства расхождением не считается |
| `refcheck.py` | сверка справки с окном: ссылки «N.NN» на существующие инструменты, имена параметров против подписей, единая запись «(0 = авто)» |

## Правка

| Скрипт | Что делает |
|---|---|
| `fix.py` | замена литерала целиком по узлу AST во всех модулях пакета сразу. Вход - JSON вида `[[старый_литерал, новый_литерал], ...]` |
| `sent.py` | замена фрагмента внутри литералов. Находит все литералы с фрагментом, применяет к ним правки и переписывает через `fix.py`. Вход - JSON вида `[[было, стало], ...]` |

Рабочий порядок один и тот же. Собрать пачку из десятка-полусотни пар,
прогнать `sent.py`, сразу за ним `python3 grid_isolines/tests/test_i18n.py`.
Пачка без проверки не считается применённой.

## Приёмка и разбор

| Скрипт | Что делает |
|---|---|
| `accept_upload.py` | приёмка выгрузочного архива для каталога: тестов внутри нет, стоп-слов ноль, обязательные файлы на месте. Код возврата 1 при браке |
| `accept.py` | распаковывает собранный архив и проверяет его: мусор, записи каталогов, разбор всех модулей, версия, стоп-слова, наличие PDF |
| `harvest.py` | складывает пачки правок в `manual/text-edits-<версия>.json` с пометкой правила у каждой пары |

## Три места, на которых правка литералов ломалась

1. `col_offset` у `ast` считается в БАЙТАХ utf-8, а не в символах. На
   кириллической строке конец литерала уезжает вперёд вдвое, и правка
   съедает следующий за литералом код.
2. Крайний пробел несёт смысл, когда сообщение приклеивается к другому.
   Разбиение по `split(" ")` его теряло, и ключ расходился с литералом.
3. Строка документации переносами не склеивается. На нулевом отступе
   каждая строка стала бы отдельной инструкцией, а докстрокой осталась бы
   первая.

Проверка после пачки дешёвая. Собрать структуру модуля через `ast.dump` с
заменой всех строк на одну заглушку и сравнить с прошлой версией.
Расходиться должны только сознательные правки кода.
