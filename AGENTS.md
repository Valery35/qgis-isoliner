# AGENTS.md — рабочий контекст Isoliner

Этот файл лежит в корне репозитория и читается первым в начале любого нового
чата. Клонируешь репозиторий, читаешь этот файл - и ты полностью в курсе, без
реконструкции по памяти. Единственный источник правды - этот репозиторий, а не
переписка. Если что-то изменилось в коде или процессе, правка идёт сюда.

## Что это

QGIS-плагин Isoliner. Группа инструментов Processing для интерполяции точечных
данных и построения изолиний на калийных месторождениях (ВКМКС, КрII).
Чистый Python/NumPy, ядро - порт GSLIB KB2D. Совместимость QGIS 3.16 - 4.99.
Версия и канонический changelog - в `grid_isolines/metadata.txt`.

**Конвенция многоканального грида пласта** (поверхности первичны, пласт -
пара поверхностей + параметры, аналог блочной модели): канал 1 - кровля,
канал 2 - подошва, каналы 3+ - параметры (содержание, минтип, ...), имена
в подписях каналов. Инструменты 3.03, 3.11 и 3D-просмотр читают канал по
номеру (по умолчанию 1).

**Дальний прицел - каркасная и блочная модели массива.** Блочная модель =
многоканальные гриды пластов (см. конвенцию выше). Каркасная модель =
нативная геометрия PolyhedralSurface, появившаяся в ядре QGIS 3.40+
(разработка Oslandia; 3D-операции над ней - плагин QSFCGAL: резка,
объединение и т.п.). Замкнутое тело пласта в 3D-просмотре
(mesh3d.bed_to_mesh_arrays: кровля + подошва + юбка, водонепроницаемое) -
готовая полиэдральная поверхность; возможный мост - инструмент экспорта
тела пласта из пары каналов в PolyhedralSurface-слой.

Не называть это «портом ArcGIS» нигде в коде, документации, описаниях.

## Инструменты (23, канонический порядок = `ALGORITHMS` в algorithms.py)

Три группы Processing. Номер в скобках - префикс в displayName (он и задаёт
порядок внутри группы); имя класса не меняется при переименовании.

**1. Грид и изолинии** (основной поток):
1. `Kriging2DAlgorithm` (kb2d) - 2D Kriging: точечный/блочный, снятие тренда, стандартная ошибка, отсев ураганных проб
2. `RasterToIsolinesAlgorithm` (isolines) - изолинии и контурные полигоны
3. `ExperimentalVariogramAlgorithm` (kb2d) - экспериментальная вариограмма
4. `VariogramMapAlgorithm` (kb2d) - вариограммная карта / анизотропия
5. `CrossValidationAlgorithm` (kb2d) - кросс-валидация (leave-one-out)
6. `ExampleWellsAlgorithm` - демо-скважины (кровля/мощность/содержание, MINTYPE, head)
7. `ProfilesAlgorithm` - профили обработки

**2. Дополнительные инструменты анализа**:
1. `CategoricalIndicatorAlgorithm` (kb2d) - категориальный индикаторный кригинг
2. `ExternalDriftKrigingAlgorithm` (kb2d) - кригинг с внешним дрейфом (KED)
3. `ExceedanceProbabilityAlgorithm` (kb2d) - карта вероятности превышения
4. `FlowGradientAlgorithm` (hydro) - гидравлический градиент и направление потока
5. `DarcyFluxAlgorithm` (hydro) - удельный расход (закон Дарси)
6. `SequentialGaussianSimAlgorithm` (kb2d) - гауссова симуляция SGS: ансамбль реализаций, среднее/стд/квантили/вероятность; nscore + sgsim в kb2d.py

**3. Разрез**:
1. `SectionAlgorithm` - разрез по линии (выдаёт определение разреза + рамку/таблицу углов)
2. `BoreholesOnSectionAlgorithm` - скважины на разрезе (опц. вход определения для общего vex)
3. `CompositionOnSectionAlgorithm` - состав пласта на разрезе (то же)
4. `SectionGridIntersectAlgorithm` - пересечение поверхностей (гридов) с разрезом
5. `SectionVectorIntersectAlgorithm` - пересечение векторов (мультислои) с разрезом: линия без Z -> вертикаль на всю высоту, линия с Z -> точка на отметке, полигон -> полоса; высота рамки из определения разреза (поля zmin/zmax от 3.01), иначе чертёж/Z-диапазон; пустые выходы не создаются; стили section_vlines/vpoints/vbands; поле src
6. `SectionTinIntersectAlgorithm` - пересечение TIN (3D-граней PolygonZ и/или меша) с разрезом: ядро `tin_section_trace` в kb2d.py (треугольник × вертикальная штора), нависание/опрокинутое воспроизводится (многозначно по высоте); 2D-трасса + опц. 3D; стиль section_tin
7. `SectionProjectAlgorithm` - проекция объектов на разрез (бета)
8. `SectionUnprojectAlgorithm` - спроецировать с разреза (бета)
9. `ShaftUnwrapAlgorithm` - развёртка стенки ствола (бета)
10. `SectionDemoAlgorithm` - создать пример для разреза (демо-векторы: разлом, маркер с Z, зона; опрокинутая TIN-складка PolygonZ)

Номера в displayName группы 3 двузначные (3.01..3.10), чтобы тулбокс QGIS не сортировал «3.10» перед «3.2». Канонический счётчик версий и changelog - в `grid_isolines/metadata.txt`.

## Сборка и релиз

- **Бюджет размера пакета**: жёсткого лимита у plugins.qgis.org нет; наш
  ориентир - ZIP до 15 МБ не думаем (сейчас ~9), 15-20 МБ - жать картинки
  руководства агрессивнее, свыше 20 МБ - выносить PDF на лендинг (крайняя
  мера: офлайн-руководство ценно на шахтных машинах без интернета).
  Растёт только `grid_isolines/doc/`; libs заморожены (14 МБ), код <1 МБ.

- **Вложенные pyqtgraph/PyOpenGL (`grid_isolines/libs/`) зачищены под сканер
  plugins.qgis.org** и входят в публикуемый ZIP. Зачистка (не откатывать при
  обновлении библиотек): удалены pyqtgraph/{console,flowchart,multiprocess,
  exporters,configfile.py,widgets/RemoteGraphicsView.py} (+ строка импорта
  RemoteGraphicsView в pyqtgraph/__init__.py), pyqtgraph/examples,
  OpenGL/{DLLS,GLES1,GLES2,GLES3,EGL,AGL,GLE} и те же в OpenGL/raw;
  заглушены `_loadUiType` (pyqtgraph/Qt/__init__.py), pickle-тест в
  OpenGL/constant.py и `MeshData.restore`. Проверка: Bandit по libs даёт
  только LOW, `import pyqtgraph.opengl` живой.
- Ветка 2.27.x выпущена в основной канал (experimental=False). Для будущих бет флаг ставить на время обкатки и снимать на стабилизации.

- **ZIP всегда `grid_isolines.zip`**, без суффикса версии.
- Перед упаковкой вычистить `__pycache__/` и `*.pyc`.
- Исходник руководства - в корневой папке `manual/`: `manual.md` (RU),
  `manual_en.md` (EN), папка `images/`, `build_pdf.sh`. Эти файлы **не** входят
  в плагин (zip собирается из `grid_isolines/`).
- PDF (RU и EN) пересобирать **всегда, когда правился `manual.md`**, и отдавать
  без напоминания: `cd manual && ./build_pdf.sh`.
- Скрипт кладёт результат в `grid_isolines/doc/Isoliner.pdf` и `…/Isoliner_en.pdf` -

- Лендинг (`site/isoliner_landing.html`): держать число карточек = числу инструментов.
- При бампе версии дописывать строку в changelog **обоих** README (`README.md`

- Структура репозитория: в корне `README.md`, `README.en.md`, `AGENTS.md`,

## Стиль руководства (RU)

- Сжатая литературная техническая проза.
- Названия элементов интерфейса - **жирным**, не «ёлочками».
- В прозе нет тире и точки с запятой. В changelog точка с запятой допустима.
- **Запрещённые слова: «честный», «честнее».** Заменять на «корректнее», «правильнее».
- В кавычках держать: «наггет», «бычьи глаза».
- Заголовки инструментов несут номер из панели (= префикс displayName):
  `# 1.1 2D Kriging (точки → растр)`, без слова «Инструмент» и без ёлочек,
  имя слово в слово как в панели. Подтемы `##` / `###` без номеров.
  Не-инструменты (Введение, Общая логика, Определение разреза, Типичные
  ситуации, Лицензия) без номеров. EN-заголовки = английский displayName.
- В PDF нет крупного титульного заголовка документа.
- `metadata.txt`: никогда сырой `%` - писать «процент» или `%%`.
- Разделители в README: RU использует ` - ` (дефис), EN ` — ` (тире).

## Журнал решённых багов (НЕ возвращать)

- Qt6 (QGIS 4): плоские enum'ы Qt местами недоступны (`Qt.WindowMinMaxButtonsHint` и т.п., шим QGIS покрывает не всё). Использовать `getattr(getattr(Qt, "WindowType", Qt), "…")` - работает в Qt5 и Qt6 (viewer3d.py).
- QGIS 4: `QgsWkbTypes.PointGeometry` заменён на `Qgis.GeometryType.Point`; сравнение со старой константой молча не совпадает. Импортировать с fallback (viewer3d.py).
- QGIS 4: `QgsGeometry.asMultiPolyline()` на одиночной LineString бросает TypeError (в QGIS 3 возвращал пустой список). Оборачивать в try/except с fallback на asPolyline (viewer3d.py).
- 3.01: пикетаж обязан включать вершины входной ломаной (равномерный linspace в изломы не попадает, профиль/полосы/3D-забор срезали углы хордой). Исправлено вставкой вершин в массив d; не убирать при рефакторинге пикетажа.

- Полигонизация поясов: только GEOS `unaryUnion` + `polygonize`. НЕ `native:splitwithlines` - на густой сети терял грани, покрытие падало вдвое.
- Гауссова модель вариограммы: принудительный минимальный наггет (устойчивость, без отрицательных весов).
- Бергштрихи депрессии: знак `WHEN @vr < @vl THEN -1` (перевёрнут после проверки в QGIS).
- Определение языка: русский только при русской локали, английский для всех прочих и неопределённой.
- Слой изолиний - над полигонами; переставлять отложенно только узел полигонов, линии не трогать.
- Степенная модель: «радиус a» = показатель ω (0<ω<2), авто=max/3 к ней не применять.
- Вариограммная карта: при главном радиусе ≤ ~3×ячейки анизотропия недостоверна - сообщать «изотропно / не определено».

## Отложено на будущее (не делать без запроса)

- **Экстраполяция верхнего хвоста в обратном nscore (SGS).** Сейчас
  `nscore_back` в `kb2d.py` интерполирует по таблице и зажимает результат к
  min/max выборки - симулированное значение не выходит за наблюдённый максимум.
  Для структурной геологии (кровля, мощность, содержание калия) это правильно.
  Но для данных с длинным правым хвостом классический SGS экстраполирует
  верхний хвост (гиперболически), чтобы реализации могли давать пики выше
  замеренного максимума, иначе занижается вероятность превышения высоких
  порогов. Каноничные случаи такого хвоста: золото и благородные металлы
  (эффект самородка, малая доля проб держит большую долю металла), драгоценные
  камни, уран, загрязнения и экология. Там верхний хвост - это и есть руда, и
  зажим к максимуму выборки систематически недооценивает богатые зоны. Если
  инструмент пойдёт в такую область - добавить модель хвоста в обратное
  преобразование. Само nscore-преобразование (вход в подбор вариограммы баллов)
  сделано корректно, речь только про обратный ход.
