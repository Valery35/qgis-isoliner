## Что это

QGIS-плагин Isoliner. Группа инструментов Processing для интерполяции точечных
данных и построения изолиний на калийных месторождениях (ВКМКС, КрII).
Чистый Python/NumPy, ядро - порт GSLIB KB2D. Совместимость QGIS 3.16 - 4.99.
Версия и канонический changelog - в `grid_isolines/metadata.txt`.

**Конвенция многоканального грида пласта** (поверхности первичны, пласт -
пара поверхностей + параметры, аналог блочной модели): канал 1 - кровля,
канал 2 - подошва, каналы 3+ - параметры (содержание, минтип, ...), имена
в подписях каналов. Инструменты 3.03, 4.04 и 3D-просмотр читают канал по
номеру (по умолчанию 1).

**Дальний прицел - каркасная и блочная модели массива.** Блочная модель =
многоканальные гриды пластов (см. конвенцию выше). Каркасная модель =
нативная геометрия PolyhedralSurface, появившаяся в ядре QGIS 3.40+
(разработка Oslandia; 3D-операции над ней - плагин QSFCGAL: резка,
объединение и т.п.). Замкнутое тело пласта в 3D-просмотре
(mesh3d.bed_to_mesh_arrays: кровля + подошва + юбка, водонепроницаемое) -
готовая полиэдральная поверхность; возможный мост - инструмент экспорта
тела пласта из пары каналов в PolyhedralSurface-слой.

Не называть это «портом ArcGIS» нигде в коде, документации, описаниях.

| `algorithms.py` | все классы алгоритмов + список `ALGORITHMS` (порядок задаёт панель); инструменты разреза и SGS тоже здесь |
| `kb2d.py` | ядро кригинга (NumPy): точечный и блочный кригинг, индикаторный/категориальный, экспериментальная вариограмма, вариограммная карта/анизотропия |
| `isolines.py` | изолинии и контурные полигоны (GEOS unaryUnion+polygonize, бикубика, Chaikin, бергштрихи) |
| `hydro.py` | гидравлический градиент и направление потока (`head_gradient`, `flow_samples`) |
| `fractal.py` | фрактальная размерность поверхности вариограммным методом (наклон лог-лог вариограммы даёт H, D = 3 - H), скользящее окно через кумулятивные суммы; box-counting, компас Ричардсона, Минковский. Чистый NumPy |
| `mesh3d.py` | регулярный грид → треугольный меш (массивы вершин/граней, запись 2DM) и водонепроницаемое тело пласта (`bed_to_mesh_arrays`: кровля + подошва + юбка), плюс `cylinder` (боковая поверхность цилиндра для стволов скважин). Без импорта QGIS, headless-тест `tests/test_mesh3d.py` |
| `mincurv.py` | гридирование минимальной кривизной: `grid_points` (снап точек к узлам + старт ближайшим значением), `solve` (SOR обходом 9 цветов по бигармонии с натяжением, натуральная граница линейной экстраполяцией - плоскость точна), `loo_estimates` (LOO с тёплого старта) и `sample_bilinear`. Без импорта QGIS, headless-тест `tests/test_mincurv.py` |
| `polyhedral.py` | полиэдральные поверхности: примитивы (куб, тетраэдр), тело пласта / складчатый пласт / свита через `mesh3d.bed_to_mesh_arrays`, сборка WKT (`POLYHEDRALSURFACE`/`TIN`/`MULTIPOLYGON` Z), разбор WKT обратно в треугольники (`wkt_to_tris`, для 3D-просмотра тел), пересечение меша с плоскостью (`slice_triangles`, для контура сечения) и аудит замкнутости оболочки. Без импорта QGIS, headless-тест `tests/test_polyhedral.py` |
| `viewer3d.py` | собственный 3D-просмотр (бета) на pyqtgraph.opengl: поверхности мешами, тела пластов, скважины стволами-цилиндрами с окраской интервалов по литологии, плоскость разреза со следом по поверхностям и контуром сечения тел (`polyhedral.slice_triangles`); вертикальное преувеличение и разнос по Z, кадрирование камеры учитывает преувеличенную высоту. Вкладка «Тела» рендерит полигональные слои с Z (полиэдр/TIN/MultiPolygon) через `polyhedral.wkt_to_tris`, каждый объект отдельным мешем своим цветом (свита разноцветная). Не зависит от Qt3D QGIS |
| `i18n.py` | словарь RU/EN (~385 записей), `tr()`, `init_from_qgis()` |
| `widgets.py` | кастомные виджеты диалогов (живой показ размера грида и пр.) |
| `about.py` | меню «Модули - Isoliner»: диалог «О плагине» (версия и changelog из metadata.txt) и открытие руководства по локали; Qt лениво, headless-тест tests/test_about.py |
| `styles/` | `iso_structure.qml`, `iso_depression.qml`, `flow_arrows.qml` |

## Инструменты (37, канонический порядок = `ALGORITHMS` в algorithms.py)

Четыре группы Processing. Номер в скобках - префикс в displayName (он и задаёт
порядок внутри группы); имя класса не меняется при переименовании. Список
`ALGORITHMS` идёт не по номерам - порядок внутри панели задаёт именно префикс
displayName, поэтому ниже инструменты перечислены по этому префиксу.

**1. Грид и изолинии** (основной поток):
- 1.1 `Kriging2DAlgorithm` (kb2d) - 2D Kriging: точечный/блочный, снятие тренда, стандартная ошибка, отсев ураганных проб
- 1.2 `RasterToIsolinesAlgorithm` (isolines) - изолинии и контурные полигоны
- 1.3 `ExperimentalVariogramAlgorithm` (kb2d) - экспериментальная вариограмма
- 1.4 `VariogramMapAlgorithm` (kb2d) - вариограммная карта / анизотропия
- 1.5 `CrossValidationAlgorithm` (kb2d) - кросс-валидация (leave-one-out)
- 1.6 `ProfilesAlgorithm` - профили обработки
- 1.7 `ExampleWellsAlgorithm` - демо-скважины (кровля/мощность/содержание, MINTYPE, head)
- 1.8 `MinCurvatureAlgorithm` (mincurv) - гридирование методом минимальной кривизны (бигармония с натяжением, SOR обходом 9 цветов). Точки → растр. Натяжение/граничное натяжение, порог невязки, макс. итераций, релаксация, анизотропия. Детерминированная альтернатива кригингу без вариограммы, часто для карт геофизических полей. Чистый NumPy, headless-тест `tests/test_mincurv.py`. Faults/breaklines - задел на будущее
- 1.9 `MethodCrossValidationAlgorithm` - LOO-кросс-валидация метода (кригинг ИЛИ минимальная кривизна) по образцу Surfer: случайная выборка N точек, фильтр области (охват + Z), буфер исключения соседей (X/Y). Кригинг через `kb2d.krige_point`, мин. кривизна через `mincurv.loo_estimates` (тёплый старт от полного решения). Выходы: слой ошибок + HTML-отчёт (`_write_cv_report`). Отдельно от 1.5 (та про модель вариограммы, эта - про метод)

**2. Дополнительные инструменты анализа**:
- 2.01 `CategoricalIndicatorAlgorithm` (kb2d) - категориальный индикаторный кригинг
- 2.02 `ExternalDriftKrigingAlgorithm` (kb2d) - кригинг с внешним дрейфом (KED)
- 2.03 `ExceedanceProbabilityAlgorithm` (kb2d) - карта вероятности превышения
- 2.04 `FlowGradientAlgorithm` (hydro) - гидравлический градиент и направление потока
- 2.05 `DarcyFluxAlgorithm` (hydro) - удельный расход (закон Дарси)
- 2.06 `SequentialGaussianSimAlgorithm` (kb2d) - гауссова симуляция SGS: ансамбль реализаций, среднее/стд/квантили/вероятность; nscore + sgsim в kb2d.py
- 2.07 `FractalDimensionAlgorithm` (fractal) - фрактальная размерность поверхности вариограммным методом (карта D = 3 - H в скользящем окне)
- 2.08 `BoxCountingAlgorithm` (fractal) - box-counting по маске
- 2.09 `LineDimensionAlgorithm` (fractal) - размерность линий и границ (компас Ричардсона)
- 2.10 `MinkowskiDimensionAlgorithm` (fractal) - размерность Минковского по векторам
- 2.11 `FractalDemoAlgorithm` (fractal) - создать пример для фракталов (демо-объекты)

**3. Разрез**:
- 3.01 `SectionAlgorithm` - разрез по линии (выдаёт определение разреза + рамку/таблицу углов)
- 3.02 `BoreholesOnSectionAlgorithm` - скважины на разрезе (опц. вход определения для общего vex)
- 3.03 `CompositionOnSectionAlgorithm` - состав пласта на разрезе (то же)
- 3.04 `SectionGridIntersectAlgorithm` - пересечение поверхностей (гридов) с разрезом
- 3.05 `SectionVectorIntersectAlgorithm` - пересечение векторов (мультислои) с разрезом: линия без Z -> вертикаль на всю высоту, линия с Z -> точка на отметке, полигон -> полоса; высота рамки из определения разреза (поля zmin/zmax от 3.01), иначе чертёж/Z-диапазон; пустые выходы не создаются; стили section_vlines/vpoints/vbands; поле src
- 3.06 `SectionTinIntersectAlgorithm` - пересечение TIN (3D-граней PolygonZ и/или меша) с разрезом: ядро `tin_section_trace` в kb2d.py (треугольник × вертикальная штора), нависание/опрокинутое воспроизводится (многозначно по высоте); 2D-трасса + опц. 3D; стиль section_tin
- 3.07 `SectionProjectAlgorithm` - проекция объектов на разрез (бета)
- 3.08 `SectionUnprojectAlgorithm` - спроецировать с разреза (бета)
- 3.09 `ShaftUnwrapAlgorithm` - развёртка стенки ствола (бета)
- 3.10 `SectionDemoAlgorithm` - создать пример для разреза (демо-векторы: разлом, маркер с Z, зона; опрокинутая TIN-складка PolygonZ)

**4. Пласт и блочная модель** (конвенция многоканального грида пласта, см. выше):
- 4.01 `BedAssembleAlgorithm` - собрать грид пласта (кровля + подошва + параметры в многоканальный растр)
- 4.02 `BedCalculatorAlgorithm` - калькулятор пласта (арифметика по каналам: мощность, разности и т.п.)
- 4.03 `BedToBlockModelAlgorithm` - грид пласта в блочную модель (деление по вертикали nz; плотность полем/каналом, ore_t = vol * dens поячеечно)
- 4.04 `SectionSurfacesToMeshAlgorithm` (mesh3d) - поверхности в 3D (треугольные меши, экспорт 2DM)
- 4.05 `DomainsToGridAlgorithm` - домены (полигоны минтипа/зон) в канал пласта
- 4.06 `ReserveDeltaAlgorithm` - разность запасов (списание): две блочные модели -> поячеечная разность объёма/тоннажа
- 4.07 `PolyhedralDemoAlgorithm` (polyhedral, бета) - демо полиэдральной поверхности (тело пласта/свита/куб/тетраэдр) как нативный PolyhedralSurface Z (QGIS 3.40+) или TIN Z; на сборках до 3.40 деградирует до MultiPolygon Z. Размещение из охвата (окна вида), параметры «Мощность», «Отметка залегания», «Пластов в свите», диапазон Z в журнал. Свита - складчатые пласты (`suite_beds`), грузятся ОТДЕЛЬНЫМИ слоями «Свита: пласт k» через `_load_suite_layers` (memory + `addLayerToLoadOnCompletion`, при сбое API - фолбэк одним слоем в sink); OUTPUT optional. Имя выходного слоя по примеру. Тело смотрится во вкладке «Тела» 3D-просмотра. Первый заход к мосту «тело пласта -> PolyhedralSurface»

Номера в displayName групп 2, 3 и 4 двузначные (2.01.., 3.01.., 4.01..), чтобы тулбокс QGIS не сортировал «3.10» перед «3.2». Канонический счётчик версий и changelog - в `grid_isolines/metadata.txt`.

## Стиль руководства (RU)

- Сжатая литературная техническая проза.
- Названия элементов интерфейса - **жирным**, не «ёлочками».
- В прозе нет тире и точки с запятой. В changelog точка с запятой допустима.
- **Запрещённые слова: «честный», «честнее».** Заменять на «корректнее», «правильнее».
- В кавычках держать: «наггет», «бычьи глаза».
- Заголовки инструментов несут номер из панели (= префикс displayName):
  `# 1.1 2D Kriging (точки → растр)`, без слова «Инструмент» и без ёлочек,
  имя слово в слово как в панели. Подтемы `##` / `###` без номеров.
  Не-инструменты (Введение, Общая логика, Определение разреза, Типичные
  ситуации, Лицензия) без номеров. EN-заголовки = английский displayName.
- В PDF нет крупного титульного заголовка документа.
- `metadata.txt`: никогда сырой `%` - писать «процент» или `%%`.
- Разделители в README: RU использует ` - ` (дефис), EN ` — ` (тире).

## Журнал решённых багов (НЕ возвращать)

- Qt6 (QGIS 4): плоские enum'ы Qt местами недоступны (`Qt.WindowMinMaxButtonsHint` и т.п., шим QGIS покрывает не всё). Использовать `getattr(getattr(Qt, "WindowType", Qt), "…")` - работает в Qt5 и Qt6 (viewer3d.py).
- QGIS 4: `QgsWkbTypes.PointGeometry` заменён на `Qgis.GeometryType.Point`; сравнение со старой константой молча не совпадает. Импортировать с fallback (viewer3d.py).
- QGIS 4: `QgsGeometry.asMultiPolyline()` на одиночной LineString бросает TypeError (в QGIS 3 возвращал пустой список). Оборачивать в try/except с fallback на asPolyline (viewer3d.py).
- viewer3d.py `rebuild()`: локальная переменная не должна называться `tr` - это функция перевода из замыкания. Любое присваивание `tr = ...` внутри функции делает `tr` локальной на всю функцию, и вызов tr("…") падает UnboundLocalError (всплыло на сцене без плоскости разреза). След трассы разреза теперь пишется в `tpts`. Регресс-тест `tests/test_viewer3d_static.py` (AST) стережёт этот класс.
- QGIS 4 (pyqtgraph 0.13): `GLViewWidget.projectionMatrix()` требует аргументы `region` и `viewport`, без них TypeError (в старом pyqtgraph вызывался без аргументов). Звать с fallback: try без аргументов, затем `projectionMatrix((0,0,w,h),(0,0,w,h))` (viewer3d.py `_pick_at`).
- QGIS 4: при включённых исключениях GDAL `gdal.Open("")` бросает RuntimeError вместо None. Все открытия растра в viewer3d.py идут через `_gdal_open` (пустой/битый источник -> None), иначе выбор своего цвета слоя ронял журнал.
- 3.01: пикетаж обязан включать вершины входной ломаной (равномерный linspace в изломы не попадает, профиль/полосы/3D-забор срезали углы хордой). Исправлено вставкой вершин в массив d; не убирать при рефакторинге пикетажа.

- Полигонизация поясов: только GEOS `unaryUnion` + `polygonize`. НЕ `native:splitwithlines` - на густой сети терял грани, покрытие падало вдвое.
- Гауссова модель вариограммы: принудительный минимальный наггет (устойчивость, без отрицательных весов).
- Бергштрихи депрессии: знак `WHEN @vr < @vl THEN -1` (перевёрнут после проверки в QGIS).
- Определение языка: русский только при русской локали, английский для всех прочих и неопределённой.
- Слой изолиний - над полигонами; переставлять отложенно только узел полигонов, линии не трогать.
- Степенная модель: «радиус a» = показатель ω (0<ω<2), авто=max/3 к ней не применять.
- Вариограммная карта: при главном радиусе ≤ ~3×ячейки анизотропия недостоверна - сообщать «изотропно / не определено».
- 1.8 Минимальная кривизна (`mincurv.solve`): векторный Якоби на 13-точечном бигармоническом шаблоне РАСХОДИТСЯ в NaN (у шаблона отрицательные коэффициенты). НЕ «упрощать» решатель обратно в векторную релаксацию за один проход. Устойчивый вариант - Гаусс-Зейдель обходом девятью цветами по (i%3, j%3): узлы одного цвета отстоят на 3+ и не попадают в шаблон друг друга, поэтому обновляются разом. Граница натуральная (линейная экстраполяция ghost-узлов в `_pad_natural`), иначе плоскость не воспроизводится точно. Старт свободных узлов - ближайшим значением данных, без него сходимость на разрежённых данных крайне медленная.
- 1.9 Кросс-валидация метода: LOO для минимальной кривизны идёт с тёплого старта от полного решения (`mincurv.loo_estimates`), иначе N полных решений слишком медленны. НЕ переписывать на «холодный» пересчёт каждой точки.

## Отложено на будущее (не делать без запроса)

- **Экстраполяция верхнего хвоста в обратном nscore (SGS).** Сейчас
  `nscore_back` в `kb2d.py` интерполирует по таблице и зажимает результат к
  min/max выборки - симулированное значение не выходит за наблюдённый максимум.
  Для структурной геологии (кровля, мощность, содержание калия) это правильно.
  Но для данных с длинным правым хвостом классический SGS экстраполирует
  верхний хвост (гиперболически), чтобы реализации могли давать пики выше
  замеренного максимума, иначе занижается вероятность превышения высоких
  порогов. Каноничные случаи такого хвоста: золото и благородные металлы
  (эффект самородка, малая доля проб держит большую долю металла), драгоценные
  камни, уран, загрязнения и экология. Там верхний хвост - это и есть руда, и
  зажим к максимуму выборки систематически недооценивает богатые зоны. Если
  инструмент пойдёт в такую область - добавить модель хвоста в обратное
  преобразование. Само nscore-преобразование (вход в подбор вариограммы баллов)
  сделано корректно, речь только про обратный ход.

## [BUG 2.48.2] nz уехал в чужой метод

Инструменты 4.02 и 4.03 имеют одинаковые имена методов и общие параметры
(DENSITY, CONTOUR). str_replace по блоку «dens/contour» зацепил processAlgorithm
калькулятора 4.02 вместо блочной модели 4.03 - параметр nz читался там, где
его нет, NameError. Урок: при правке классов с одинаковыми методами якорь
должен включать уникальный признак нужного класса (имя параметра, строку
справки), а после - grep, в каком классе оказалась вставка. Так дважды
подряд (2.48.2 nz, 2.48.3 DENS_BAND) правки для 4.03 падали в 4.02:
ПРОВЕРЯТЬ каждую вставку grep-ом по имени класса, а не только синтаксис.

## [BUG 2.47.7] _default_opts от пустого пути

_default_opts(source) считает каналы через gdal.Open - вызов с "" даёт
RuntimeError (в QGIS 4 исключения GDAL включены). Правило: дефолтные
опции слоя строить только от настоящего lyr.source(); если слоя нет -
выходить, а не подставлять пустышку.

## Вставка картинок в руководство

Ловушка: текстовые якоря могут оказаться ВНУТРИ alt-текста существующей
картинки ![...](...) - вставка туда ломает markdown, и хвост
«.](images/...)» вываливается в PDF (случай ui_toolbox, 2.47.4). Перед
вставкой проверять, что якорь не внутри alt; после вставок прогонять
контроль целостности: нет строк, начинающихся с «.](», и в каждой строке
баланс «![» и «](». Плюс grep PDF на имена старых картинок.

## Точка с запятой

«;» - стоп-символ публикуемых текстов: разбивать на предложения или
заменять запятой/союзом. В коде и в changelog metadata.txt допустима.

## Слово «число»

В подписях параметров и везде, где считаются штуки, - «количество»
(«Количество лагов», «Мин. количество точек»). «Число» допустимо только
в математическом смысле величины: «случайное число», «безразмерное
число», «абсолютное число (не доля)». Тип поля в таблицах атрибутов -
«число» (тип данных), это не счёт.

## Голос публикуемых текстов

Статьи, посты, описания - от лица компании: «мы», не «я». Глагол «делать»
о работе - стоп-слово: «создаём», «разрабатываем». Эталон первой фразы:
«Мы создаем софт для горно-геологических служб калийных рудников».

## Проверка публикаций на Хабре

При выгрузке статьи ссылка вида [![](<>)](https://sourcecraft.dev/) в конце
кодовых блоков - это штатная кнопка Хабра «открыть в SourceCraft», а не
мусор из буфера. Не флажить. Настоящий мусор ищется в тексте: стоп-слова,
устаревшие счётчики инструментов, расхождения подписей с кодом.
