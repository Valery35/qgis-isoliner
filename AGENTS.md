## Что это

QGIS-плагин Isoliner. Группы инструментов Processing для интерполяции точечных
данных, построения изолиний и работы с рельефом на калийных месторождениях
(ВКМКС, КрII).
Чистый Python/NumPy, ядро - порт GSLIB KB2D. Совместимость QGIS 3.16 - 4.99.
Версия и канонический changelog - в `grid_isolines/metadata.txt`.

**Конвенция многоканального грида пласта** (поверхности первичны, пласт -
пара поверхностей + параметры, аналог блочной модели): канал 1 - кровля,
канал 2 - подошва, каналы 3+ - параметры (содержание, минтип, ...), имена
в подписях каналов. Инструменты 3.03, 4.04 и 3D-просмотр читают канал по
номеру (по умолчанию 1).

**Дальний прицел - каркасная и блочная модели массива.** Блочная модель =
многоканальные гриды пластов (см. конвенцию выше). Каркасная модель =
нативная геометрия PolyhedralSurface, появившаяся в ядре QGIS 3.40+
(разработка Oslandia; 3D-операции над ней - плагин QSFCGAL: резка,
объединение и т.п.). Замкнутое тело пласта в 3D-просмотре
(mesh3d.bed_to_mesh_arrays: кровля + подошва + юбка, водонепроницаемое) -
готовая полиэдральная поверхность; возможный мост - инструмент экспорта
тела пласта из пары каналов в PolyhedralSurface-слой.

Не называть это «портом ArcGIS» нигде в коде, документации, описаниях.

## Инструменты (51, канонический порядок = `ALGORITHMS` в algorithms.py)

Шесть групп Processing. В релизе 3.0.0 группа «Топография» встала второй, ярлыки прежних групп 2-5 сдвинуты в 3-6 вместе с префиксами displayName, идентификаторы групп и name() инструментов не менялись. Номер в скобках - префикс в displayName (он и задаёт
порядок внутри группы); имя класса не меняется при переименовании. Список
`ALGORITHMS` идёт не по номерам - порядок внутри панели задаёт именно префикс
displayName, поэтому ниже инструменты перечислены по этому префиксу.

**1. Грид и изолинии** (основной поток):
Группа 1 использует ДВУЗНАЧНУЮ нумерацию (1.01…1.10) - `displayName` сортируется лексикографически, поэтому одиночные 1.1/1.10 встали бы не по порядку. При добавлении инструмента в группу держи двузначный номер. Порядок: подготовка данных → интерполяция → изолинии → вариограммы → кросс-валидации рядом → сервис/демо в конце.
- 1.01 `DeclusteringAlgorithm` (declus) - ячеистая декластеризация (GSLIB declus): веса обратно локальной плотности, представительное декластеризованное среднее для запасов и SK-среднего. Авто/ручной размер ячейки, слой точек с полем wt, HTML-отчёт. Номер 1.01 (двузначная нумерация группы 1, шаг подготовки данных сортируется первым)
- 1.02 `Kriging2DAlgorithm` (kb2d) - 2D Kriging: точечный/блочный, снятие тренда, стандартная ошибка, отсев ураганных проб
- 1.03 `MinCurvatureAlgorithm` (mincurv) - гридирование методом минимальной кривизны (бигармония с натяжением, SOR обходом 9 цветов). Точки → растр. Натяжение/граничное натяжение, порог невязки, макс. итераций, релаксация, анизотропия. Детерминированная альтернатива кригингу без вариограммы, часто для карт геофизических полей. Чистый NumPy, headless-тест `tests/test_mincurv.py`. Faults/breaklines - задел на будущее
- 1.04 `RasterToIsolinesAlgorithm` (isolines) - изолинии и контурные полигоны
- 1.05 `ExperimentalVariogramAlgorithm` (kb2d) - экспериментальная вариограмма. Принимает поле весов декластеризации (wt из 1.01): пара с весом w_i*w_j, npairs сырой
- 1.06 `VariogramMapAlgorithm` (kb2d) - вариограммная карта / анизотропия. Принимает поле весов декластеризации (wt из 1.01)
- 1.07 `CrossValidationAlgorithm` (kb2d) - кросс-валидация (leave-one-out). Принимает поле весов декластеризации (wt из 1.01) - метрики взвешиваются (`_weighted_cv_metrics`)
- 1.08 `MethodCrossValidationAlgorithm` - LOO-кросс-валидация метода (кригинг ИЛИ минимальная кривизна) по образцу Surfer: случайная выборка N точек, фильтр области (охват + Z), буфер исключения соседей (X/Y). Кригинг через `kb2d.krige_point`, мин. кривизна через `mincurv.loo_estimates` (тёплый старт от полного решения). Выходы: слой ошибок + HTML-отчёт (`_write_cv_report`). Отдельно от 1.5 (та про модель вариограммы, эта - про метод). Принимает поле весов wt (взвешенные метрики)
- 1.09 `ProfilesAlgorithm` - профили обработки
- 1.10 `ExampleWellsAlgorithm` - демо-скважины (кровля/мощность/содержание, MINTYPE, head)
- 1.11 `GeophysProfilesDemoAlgorithm` (geodemo) - демо профилей, два режима: электроразведка (ρк пятном, ЕП, ВП, z, rho_true) и оседания (мульда по турам: tour, settle, settle_true). Аномалия компактным пятном, не полосой. Имя слоя адаптивное по режиму (электроразведка/оседания); демо-скважины разреза (4.10) названы «Скважины разреза (демо)», чтобы не совпадать с 1.10


**2. Топография** (GROUP_TOPO/topography, добавлена в 3.0.0):
- 2.01 `DemDownloadAlgorithm` (dem_glo30) - загрузка ЦМР Copernicus GLO-30 по рамке: /vsicurl/ без ключей, VRT без швов, варп в метрическую СК (СК проекта или UTM по центру), гидрокоррекция флажком по умолчанию, градусная целевая СК отклоняется
- 2.02 `TopobaseDownloadAlgorithm` (osm_overpass) - топооснова OSM: водотоки (готовые тальвеги), водоёмы (замкнутые way, мультиполигоны пока пропускаются), вершины с ele, обрывы/насыпи, береговая линия. Атрибуция ODbL в журнале
- 2.03 `Topo2RasterAlgorithm` (topo_t2r) - рельеф из векторов: точки/изолинии жёсткие узлы, тальвеги монотонное падение (OSM и 2.06 подходят как есть), обрывы барьеры (сама линия шириной в ячейку - промежуточная высота, ограничение v1), озёра плоскости (уровень из поля или минимум берега). СК первого слоя, метрическая
- 2.04 `TopoFillDepressionsAlgorithm` (hydro_fill) - заполнение понижений с отчётом (поднято ячеек, макс. подъём)
- 2.05 `FlowD8Algorithm` (topo_flow) - направления (коды ESRI, nodata=255) + аккумуляция, флажок заполнения по умолчанию
- 2.06 `RiverNetworkAlgorithm` (topo_flow) - речная сеть: поля order (Стралер), acc_out, length_m, вершины вниз по течению
- 2.07 `BasinsAlgorithm` (topo_flow) - бассейны: точки замыкания с притяжкой к максимуму аккумуляции или устья по порогу, полигоны через gdal.Polygonize (диагональные части объединяются unaryUnion) + опц. растр меток
- 2.08 `SlopeAspectAlgorithm` (topo_surface) - уклон и экспозиция Horn 3x3
- 2.09 `PeaksAlgorithm` (topo_surface) - вершины: радиус + минимальное превышение
- 2.10 `TopoDemoReliefAlgorithm` (demo_relief) - демо-рельеф, флажок int16 для поставки демо

Общее для группы 2: все выходы кладутся в группу «Топография» дерева слоёв
через `_topo_group_layer` (LayerDetails.groupName, QGIS 3.24+, на старых
сборках тихий фолбэк). Целевая СК в 2.01 и 2.10 принимает пользовательские
СК без кода EPSG - в варп уходит WKT (`dst_wkt` в dem_glo30.fetch_dem,
`wkt` в demo_relief.write_geotiff). Не возвращать проверку «только EPSG»:
локальные шахтные сетки - основной кейс (всплыло на USER:100001, QGIS 4.0.3).
Узлы выходных слоёв сворачиваются постпроцессором
`_CollapseNodePostProcessor` (синглтон: QGIS хранит только указатель на
постпроцессор, экземпляр обязан пережить вызов - не заводить локальным).

**4. Разрез**:
- 4.01 `SectionAlgorithm` - разрез по линии (выдаёт определение разреза + рамку/таблицу углов)
- 4.02 `BoreholesOnSectionAlgorithm` - скважины на разрезе (опц. вход определения для общего vex)
- 4.03 `CompositionOnSectionAlgorithm` - состав пласта на разрезе (то же)
- 4.04 `SectionGridIntersectAlgorithm` - пересечение поверхностей (гридов) с разрезом
- 4.05 `SectionVectorIntersectAlgorithm` - пересечение векторов (мультислои) с разрезом: линия без Z -> вертикаль на всю высоту, линия с Z -> точка на отметке, полигон -> полоса; высота рамки из определения разреза (поля zmin/zmax от 4.01), иначе чертёж/Z-диапазон; пустые выходы не создаются; стили section_vlines/vpoints/vbands; поле src
- 4.06 `SectionTinIntersectAlgorithm` - пересечение TIN (3D-граней PolygonZ и/или меша) с разрезом: ядро `tin_section_trace` в kb2d.py (треугольник × вертикальная штора), нависание/опрокинутое воспроизводится (многозначно по высоте); 2D-трасса + опц. 3D; стиль section_tin
- 4.07 `SectionProjectAlgorithm` - проекция объектов на разрез (бета)
- 4.08 `SectionUnprojectAlgorithm` - спроецировать с разреза (бета)
- 4.09 `ShaftUnwrapAlgorithm` - развёртка стенки ствола (бета)
- 4.10 `SectionDemoAlgorithm` - создать пример для разреза (демо-векторы: разлом, маркер с Z, зона; опрокинутая TIN-складка PolygonZ)

**5. Пласт и блочная модель** (конвенция многоканального грида пласта, см. выше):
- 5.01 `BedAssembleAlgorithm` - собрать грид пласта (кровля + подошва + параметры в многоканальный растр)
- 5.02 `BedCalculatorAlgorithm` - калькулятор пласта (арифметика по каналам: мощность, разности и т.п.)
- 5.03 `BedToBlockModelAlgorithm` - грид пласта в блочную модель (деление по вертикали nz; плотность полем/каналом, ore_t = vol * dens поячеечно)
- 5.04 `SectionSurfacesToMeshAlgorithm` (mesh3d) - поверхности в 3D (треугольные меши, экспорт 2DM)
- 5.05 `DomainsToGridAlgorithm` - домены (полигоны минтипа/зон) в канал пласта
- 5.06 `ReserveDeltaAlgorithm` - разность запасов (списание): две блочные модели -> поячеечная разность объёма/тоннажа
- 5.07 `PolyhedralDemoAlgorithm` (polyhedral, бета) - демо полиэдральной поверхности (тело пласта/свита/куб/тетраэдр) как нативный PolyhedralSurface Z (QGIS 3.40+) или TIN Z; на сборках до 3.40 деградирует до MultiPolygon Z. Размещение из охвата (окна вида), параметры «Мощность», «Отметка залегания», «Пластов в свите», диапазон Z в журнал. Свита - складчатые пласты (`suite_beds`), грузятся ОТДЕЛЬНЫМИ слоями «Свита: пласт k» через `_load_suite_layers` (memory + `addLayerToLoadOnCompletion`, при сбое API - фолбэк одним слоем в sink); OUTPUT optional. Имя выходного слоя по примеру. Тело смотрится во вкладке «Тела» 3D-просмотра. Первый заход к мосту «тело пласта -> PolyhedralSurface»

Номера в displayName групп 2, 3 и 4 двузначные (3.01.., 4.01.., 5.01..), чтобы тулбокс QGIS не сортировал «4.10» перед «3.2». Канонический счётчик версий и changelog - в `grid_isolines/metadata.txt`.

## Журнал решённых багов (НЕ возвращать)

- Qt6 (QGIS 4): плоские enum'ы Qt местами недоступны (`Qt.WindowMinMaxButtonsHint` и т.п., шим QGIS покрывает не всё). Использовать `getattr(getattr(Qt, "WindowType", Qt), "…")` - работает в Qt5 и Qt6 (viewer3d.py).
- QGIS 4: `QgsWkbTypes.PointGeometry` заменён на `Qgis.GeometryType.Point`; сравнение со старой константой молча не совпадает. Импортировать с fallback (viewer3d.py).
- QGIS 4: `QgsGeometry.asMultiPolyline()` / `asMultiPoint()` / `asMultiPolygon()` на одиночной геометрии бросают TypeError (в QGIS 3 возвращали пустой список). Оборачивать в try/except с fallback на asPolyline/asPoint/asPolygon (viewer3d.py, Topo2RasterAlgorithm в algorithms.py) либо проверять QgsWkbTypes.isMultiType до вызова (density, section demo). Всплывало дважды: viewer3d и обкатка 3.0.2 Topo2Raster на живых слоях OSM.
- viewer3d.py `rebuild()`: локальная переменная не должна называться `tr` - это функция перевода из замыкания. Любое присваивание `tr = ...` внутри функции делает `tr` локальной на всю функцию, и вызов tr("…") падает UnboundLocalError (всплыло на сцене без плоскости разреза). След трассы разреза теперь пишется в `tpts`. Регресс-тест `tests/test_viewer3d_static.py` (AST) стережёт этот класс.
- QGIS 4 (pyqtgraph 0.13): `GLViewWidget.projectionMatrix()` требует аргументы `region` и `viewport`, без них TypeError (в старом pyqtgraph вызывался без аргументов). Звать с fallback: try без аргументов, затем `projectionMatrix((0,0,w,h),(0,0,w,h))` (viewer3d.py `_pick_at`).
- QGIS 4: при включённых исключениях GDAL `gdal.Open("")` бросает RuntimeError вместо None. Все открытия растра в viewer3d.py идут через `_gdal_open` (пустой/битый источник -> None), иначе выбор своего цвета слоя ронял журнал.
- 3.01: пикетаж обязан включать вершины входной ломаной (равномерный linspace в изломы не попадает, профиль/полосы/3D-забор срезали углы хордой). Исправлено вставкой вершин в массив d; не убирать при рефакторинге пикетажа.

- Полигонизация поясов: только GEOS `unaryUnion` + `polygonize`. НЕ `native:splitwithlines` - на густой сети терял грани, покрытие падало вдвое.
- Гауссова модель вариограммы: принудительный минимальный наггет (устойчивость, без отрицательных весов).
- Бергштрихи депрессии: знак `WHEN @vr < @vl THEN -1` (перевёрнут после проверки в QGIS).
- Определение языка: русский только при русской локали, английский для всех прочих и неопределённой.
- Слой изолиний - над полигонами; переставлять отложенно только узел полигонов, линии не трогать.
- Степенная модель: «радиус a» = показатель ω (0<ω<2), авто=max/3 к ней не применять.
- Вариограммная карта: при главном радиусе ≤ ~3×ячейки анизотропия недостоверна - сообщать «изотропно / не определено».
- 1.03 Минимальная кривизна (`mincurv.solve`): векторный Якоби на 13-точечном бигармоническом шаблоне РАСХОДИТСЯ в NaN (у шаблона отрицательные коэффициенты). НЕ «упрощать» решатель обратно в векторную релаксацию за один проход. Устойчивый вариант - Гаусс-Зейдель обходом девятью цветами по (i%3, j%3): узлы одного цвета отстоят на 3+ и не попадают в шаблон друг друга, поэтому обновляются разом. Граница натуральная (линейная экстраполяция ghost-узлов в `_pad_natural`), иначе плоскость не воспроизводится точно. Старт свободных узлов - ближайшим значением данных, без него сходимость на разрежённых данных крайне медленная.
- 1.08 Кросс-валидация метода: LOO для минимальной кривизны идёт с тёплого старта от полного решения (`mincurv.loo_estimates`), иначе N полных решений слишком медленны. НЕ переписывать на «холодный» пересчёт каждой точки.

## Отложено на будущее (не делать без запроса)

- **Экстраполяция верхнего хвоста в обратном nscore (SGS).** Сейчас
  `nscore_back` в `kb2d.py` интерполирует по таблице и зажимает результат к
  min/max выборки - симулированное значение не выходит за наблюдённый максимум.
  Для структурной геологии (кровля, мощность, содержание калия) это правильно.
  Но для данных с длинным правым хвостом классический SGS экстраполирует
  верхний хвост (гиперболически), чтобы реализации могли давать пики выше
  замеренного максимума, иначе занижается вероятность превышения высоких
  порогов. Каноничные случаи такого хвоста: золото и благородные металлы
  (эффект самородка, малая доля проб держит большую долю металла), драгоценные
  камни, уран, загрязнения и экология. Там верхний хвост - это и есть руда, и
  зажим к максимуму выборки систематически недооценивает богатые зоны. Если
  инструмент пойдёт в такую область - добавить модель хвоста в обратное
  преобразование. Само nscore-преобразование (вход в подбор вариограммы баллов)
  сделано корректно, речь только про обратный ход.

## [BUG 2.48.2] nz уехал в чужой метод

Инструменты 4.02 и 4.03 имеют одинаковые имена методов и общие параметры
(DENSITY, CONTOUR). str_replace по блоку «dens/contour» зацепил processAlgorithm
калькулятора 4.02 вместо блочной модели 4.03 - параметр nz читался там, где
его нет, NameError. Урок: при правке классов с одинаковыми методами якорь
должен включать уникальный признак нужного класса (имя параметра, строку
справки), а после - grep, в каком классе оказалась вставка. Так дважды
подряд (2.48.2 nz, 2.48.3 DENS_BAND) правки для 4.03 падали в 4.02:
ПРОВЕРЯТЬ каждую вставку grep-ом по имени класса, а не только синтаксис.

## [BUG 2.47.7] _default_opts от пустого пути

_default_opts(source) считает каналы через gdal.Open - вызов с "" даёт
RuntimeError (в QGIS 4 исключения GDAL включены). Правило: дефолтные
опции слоя строить только от настоящего lyr.source(); если слоя нет -
выходить, а не подставлять пустышку.
